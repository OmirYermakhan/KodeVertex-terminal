# Схемы картинкой в ответах Claude

## Зачем
Claude объясняет общую картину ASCII-схемами («│ ▼ ──») — стена текста. Владелец хочет видеть
настоящие схемы: блоки, стрелки, графы связей, при случае — диаграммы с цифрами. Условия владельца:
безопасно, без заметного расхода токенов, без влияния на то, как ИИ думает.

## Цели
- Блок ` ```mermaid ` в ответе показывается картинкой: в карточке ответа, итоговой карточке и в режиме чтения ⌘R.
- В изменениях `.md`-файла (Write/Edit) — схемы тоже можно увидеть картинкой.
- Claude знает, что схемы надо рисовать через mermaid, а не ASCII (короткая подсказка при запуске).
- Под картинкой: «Исходник» (показать/скрыть код) и «Копировать».

## Не цели / анти-цели
- Не рисовать произвольный HTML/SVG от модели, не превращать ASCII в картинки.
- Никаких сетевых запросов, внешних шрифтов, исполнения кода из ответа.
- Не навязывать схемы: подсказка просит рисовать только когда схема реально помогает.
- Ошибка синтаксиса не ломает карточку: показывается исходник и пометка «Схему не удалось нарисовать».

## Подходы
- **A. Mermaid (выбран).** Стандарт (GitHub, Notion), блок-схемы, графы, sequence, timeline, mindmap,
  pie, xychart. Офлайн, тема из цветов приложения. Цена — ~1–2 МБ, грузится лениво при первой схеме.
- B. Claude пишет SVG/HTML сам — непредсказуемо, долго, опасно (нужна песочница). Отклонён.
- C. Распознавать ASCII-схемы — ненадёжно. Отклонён.

## Решения
- Безопасность: `mermaid.initialize({ securityLevel: 'strict', startOnLoad: false, htmlLabels: false })`;
  готовый SVG показывается как `<img src=blob:…>` — скрипты в такой картинке не исполняются вообще.
  CSP уже разрешает `img-src blob:`. Библиотека — из npm, в бандле, `import()` лениво.
- Токены: подсказка ~60 токенов через `--append-system-prompt` (кэшируемое начало), переключатель в
  настройках «Схемы картинкой» (по умолчанию вкл.); выключен — флага нет, поведение как раньше.
  Текст подсказки (рус./англ. — на усмотрение, коротко): в этом терминале блоки ```mermaid показываются
  картинкой; когда схема реально помогает понять (архитектура, поток, связи, шаги) — рисуй её mermaid,
  а не ASCII-псевдографикой; не добавляй схемы без нужды.
- Стриминг: пока ответ печатается, блок mermaid показывается кодом с подписью «Схема рисуется…»;
  рисуется после конца ответа (незакрытый блок не рендерим).
- Тема: themeVariables из CSS-переменных текущей темы (фон, текст, акцент, линии); при смене темы — перерисовка.
  Шрифт — системный (внешние шрифты в `<img>` не грузятся).
- Кэш: результат по (тема, исходник) в памяти — повторная отрисовка ленты не вызывает mermaid снова.
- Выключенный переключатель отключает и подсказку, и отрисовку (блоки — обычным кодом).
- `.md` в карточке изменения: кнопка «Как документ» показывает Markdown нового содержимого (`after`)
  со схемами; по умолчанию — обычный вид изменений.

## Оставлено исполнителю
Точная вёрстка подписи/кнопок (в стиле `.md-code`/`.md-copy`), размер и прокрутка широкой схемы
(не шире карточки, горизонтальная прокрутка при необходимости), моки mermaid в jsdom-тестах.
