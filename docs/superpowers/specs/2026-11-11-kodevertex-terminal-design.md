# KodeVertex Terminal — дизайн

Дата: 2026-11-11 · Статус: утверждён владельцем

## 1. Зачем

Владелец (KodeVertex) делает терминал **для себя**, но открытым: публичный репозиторий
`KodeVertex-terminal` на GitHub, бесплатные сборки для всех.

Причина: функциональность Warp устраивает, а дизайн нет. В Warp **трудно читать длинный
текст**: документацию, учебные материалы и особенно ответы Claude Code. В разговоре с агентом
непонятно, где вопрос, где объяснение, где действия агента, а где итог.

Основная работа в терминале будет идти **с Claude Code**.

**Успех:** длинный ответ Claude или документацию можно спокойно прочитать и сразу понять
структуру: кто что написал, что агент сделал, чем всё закончилось, какой агент работает прямо
сейчас и сколько контекста потрачено.

## 2. Цели, не-цели, анти-цели

**Цели**
- Функции на уровне Warp: блоки команд, строка ввода внизу, вкладки, разделение экрана,
  горячие клавиши, история, палитра команд.
- Режим чтения: длинный текст показывается как документ, а не как поток моноширинных символов.
- Глубокая интеграция с Claude Code: карточки сообщений, нижняя панель агентов, статус-бар.
- Темы оформления, включая тему как в Android Studio владельца.
- Открытый код и скачиваемые сборки.

**Не-цели (первая версия)**
- Собственный ИИ-агент. Владелец сделает его позже и сам решит, где его показывать.
  Сейчас нужен только «разъём» (см. §7).
- Облачные функции Warp: аккаунты, синхронизация, Warp Drive, совместная работа.
- Своя ИИ-модель, оплата, телеметрия.

**Анти-цели (провал, даже если всё «работает»)**
- Текст читается так же тяжело, как в Warp: мелко, плотно, без иерархии.
- Интерфейс шумный, с кучей панелей, иконок и цветов, которые отвлекают от текста.
- Обычный терминал работает хуже стандартного: ломаются vim, htop, ssh, цвета или вставка.
- Интеграция с Claude держится на разборе текста с экрана и ломается при обновлении Claude Code.

## 3. Ограничения

- Основная платформа — macOS (Apple Silicon, macOS 27). Код с самого начала кроссплатформенный,
  чтобы позже выпустить Windows и Linux.
- Лицензия MIT, репозиторий публичный: `KodeVertex-terminal` на аккаунте GitHub владельца.
- В истории git нет упоминаний ИИ в коммитах (требование владельца).
- На машине уже есть Node 24 и Claude Code 2.1.x, Rust нужно установить.
- Аккаунта Apple Developer нет: сборки **без подписи и нотаризации** (ad-hoc подпись).
  В README есть инструкция первого запуска (правый клик → «Открыть» или `xattr -dr com.apple.quarantine`).
  Подпись можно добавить позже, это затронет только CI.

## 4. Решения владельца

### 4.1 Режим чтения (макет `docs/design-mockups/01-reading-modes.html`, вариант B)
Длинный текст с разметкой (заголовки, списки, код) показывается **карточкой для чтения**:
- текст набран пропорциональным шрифтом, код — моноширинным;
- заголовки, списки, таблицы и ссылки отрисованы по-настоящему;
- ширина строки ограничена (~70–76 символов), увеличены межстрочные интервалы;
- блоки кода с подсветкой синтаксиса и кнопкой «копировать».

### 4.2 Слои сообщений Claude (макет `02-message-layers.html`, вариант B)
- **Вопрос пользователя** — «пузырь» справа, как в мессенджере.
- **Текст агента** — сплошная карточка с цветной полосой слева и подписью «Имя · Модель».
- **Действия агента** (запуск команды, правка файла, поиск) — пунктирная рамка с иконкой.
  Правка файла показывается как diff «было/стало».
- **Итог** — отдельная выделенная карточка.

### 4.3 Окно (макет `04-main-window.html` — основной)
Сверху вниз:
1. **Вкладки.** Точка на вкладке показывает, что в ней сейчас работает агент.
2. **Лента блоков**, как в Warp: обычные команды с выводом и сообщения Claude (§4.2).
3. **Нижняя панель агентов** (над строкой ввода):
   - одна строка на агента: статус-точка (работает / ждёт вас / готово), имя,
     плашка модели, что делает сейчас, время, токены;
   - помощники показаны со сдвигом и знаком `└` под агентом, который их запустил;
   - `⌘↓` — перейти в панель, `↑↓` — выбрать агента, `↵` — раскрыть подробности
     (что делает сейчас, что уже сделал, шаг N из M), `esc` — вернуться к вводу, `⌘J` — скрыть панель;
   - **без аватаров** (владелец отказался от пиксельных аватаров).
4. **Строка ввода**, как в Warp: многострочная, с подсказкой `⌘↵ отправить агенту`.
   **Без** плашек папки и ветки — они есть в статус-баре.
5. **Статус-бар:** режим (◆ CLAUDE) · какой агент работает сейчас · проект · ветка · модель ·
   контекст (полоска + `84k / 200k`) · время.

### 4.4 Горячие клавиши (как в Warp)
| Действие | Клавиши |
|---|---|
| Разделить вправо / вниз | `⌘D` / `⌘⇧D` |
| Новая вкладка / закрыть панель | `⌘T` / `⌘W` |
| Перейти между панелями | `⌥⌘←→↑↓` |
| Выбрать блок выше / ниже | `⌘↑` / `⌘↓` (в ленте) |
| Скопировать вывод блока | `⌘⇧C` |
| Поиск / история / палитра | `⌘F` / `⌃R` / `⌘P` |
| Панель агентов | см. §4.3 |

Конфликт `⌘↓`: в ленте он выбирает блок ниже, а из последнего блока или из строки ввода
переводит фокус в панель агентов. Окончательную раскладку уточняет билдер, сохраняя логику
«стрелки двигают по вертикали: лента → агенты → ввод».

### 4.5 Темы (макет `03-themes.html`)
Пять встроенных тем, переключаются в настройках сразу, без перезапуска:
A KodeVertex (фирменная) · B Тёплый графит · C Сине-серый · D Светлая бумага ·
**E Android Studio — по умолчанию** (New UI Dark: фон `#1e1f22`, панели `#2b2d30`,
текст `#bcbec4`, акцент `#3574f0`, шрифт JetBrains Mono, подсветка кода как в IDE).
Точные цвета — в CSS-переменных макета `03-themes.html`.

### 4.6 Шрифты (макет `05-fonts.html`, вариант A)
- **По умолчанию — как в Android Studio:** текст и интерфейс набраны **Inter**, код, команды и вывод shell — **JetBrains Mono**.
  Шрифты встроены в приложение, системная установка не нужна. Кириллица обязательна.
- **В настройках (раздел «Шрифты») с живым предпросмотром:**
  - выбор шрифта текста из списка: Inter, Geist, IBM Plex Sans, PT Serif, системный (SF Pro)
    и любой установленный в системе;
  - выбор шрифта кода: JetBrains Mono, Geist Mono, IBM Plex Mono, Fira Code, SF Mono
    и любой установленный моноширинный;
  - размер текста (кнопки − / +, шаг 1 px, по умолчанию 16) и отдельно размер кода;
  - межстрочный интервал (1.5 / 1.6 / 1.7 / 1.8, по умолчанию 1.7);
  - лигатуры в коде: вкл/выкл.
- **Быстро, без настроек:** `⌘=` / `⌘−` меняет размер, `⌘0` сбрасывает его.
  Те же действия доступны в палитре команд (`⌘P`).
- Настройки шрифтов не зависят от темы: смена темы не сбрасывает шрифт.

### 4.7 Уведомления об агентах (добавлено владельцем)
Нужно сразу понимать, что агент закончил, ждёт ответа или упал, даже если смотришь в другую
вкладку или в другую программу.
- **События:** агент (главный или субагент) **завершил задачу** · **ждёт вашего ответа или разрешения** ·
  **ошибка** (упал или прерван) · команда shell длиной больше 10 с завершилась (как в Warp; из плана 2).
- **Внутри приложения:** всплывающая карточка справа внизу над статус-баром: «✓ Архитектор
  закончил: модуль оплаты», «! Главный ждёт ответа», «✕ Стили: ошибка». Карточка исчезает через 6 с,
  а клик по ней переводит во вкладку и к нужному агенту. Цвета: готово — `add`, ждёт — `warn`,
  ошибка — `del`.
- **Системное уведомление macOS:** приходит, когда окно не в фокусе или событие случилось
  не в текущей вкладке. Клик по уведомлению открывает окно на нужной вкладке.
- **Вкладка:** точка меняет цвет: синяя пульсирует — работает, жёлтая — ждёт вас, зелёная — готово
  (пока вкладку не открыли), красная — ошибка.
- **Иконка в Dock:** счётчик агентов, которые ждут ответа.
- **Звук:** короткий тихий сигнал при «ждёт вас» и «готово». Выключается в настройках.
- **Настройки («Уведомления»):** вкл/выкл отдельно для системных уведомлений, звука,
  уведомлений о субагентах (по умолчанию — только главный агент и «ждёт вас» от любого)
  и о долгих командах shell.
- Реализуется в плане 3 вместе с интеграцией Claude, а долгие команды shell — в плане 2.

## 5. Технологии (решение исполнителя, владелец согласился «го»)
- **Tauri 2** (Rust + WebView) — лёгкое кроссплатформенное приложение.
- **React + TypeScript + Vite** — интерфейс.
- **xterm.js** с WebGL-рендером — эмуляция терминала для shell и полноэкранных программ.
- **portable-pty** (Rust) — запуск shell пользователя.
- **Блоки** — через shell integration (OSC 133), которую терминал сам подключает для zsh
  (позже bash и fish), не трогая `~/.zshrc` пользователя без спроса.
- **Claude** — запуск `claude` с `--output-format stream-json --input-format stream-json`
  (+ `--include-partial-messages` для потоковой печати). Из событий берутся сообщения,
  вызовы инструментов, субагенты (по `parent_tool_use_id`), модель и расход токенов.
  Никакого разбора текста с экрана.
- **Markdown** — рендер карточек (например, `react-markdown` + подсветка Shiki).
- **Сборка и релизы** — GitHub Actions → `.dmg` в GitHub Releases.

## 6. Как совмещаются shell и Claude
- Обычный ввод уходит в shell, как в Warp.
- Сообщение агенту отправляется через `⌘↵` (или префикс, на выбор билдера) и открывает
  или продолжает Claude-сессию этой вкладки. Её события рисуются карточками в той же ленте.
- Полноэкранные программы (vim, htop, less, интерактивный `claude` без флагов)
  получают весь экран xterm, как в обычном терминале.

### 6.1 Строка ввода
Строка ввода своя, как в Warp: многострочная, с курсором мышью, выделением и автодополнением
путей и команд. Плагины zsh, перехватывающие ввод
(oh-my-zsh, autosuggestions, vi-mode, свои bindkey), в этой строке не работают.
`⌃R` открывает свой поиск по истории (история читается из `~/.zsh_history`).
При запуске полноэкранной программы ввод уходит напрямую в программу.

### 6.1a Подсказки путей, как в Warp (добавлено владельцем)
- При вводе `cd ` сразу появляется выпадающий список **папок** текущего каталога (с учётом уже
  набранной части пути, `~`, `..`, вложенных путей вроде `src/comp…`). Для других команд
  (`cat`, `vim`, `code`, `ls`…) — папки и файлы.
- Справа от списка — **превью «что внутри»** подсвеченного элемента: для папки — её содержимое
  (первые ~20 элементов, папки сверху, со значками), для текстового файла — первые строки.
- Навигация: `↑↓` выбор, `Tab`/`→` подставить, `↵` подставить и выполнить для `cd`,
  `esc` закрыть. Поиск нечёткий (`cmp` находит `components`), скрытые файлы — только если набрана `.`.
- Список строится в Rust (чтение каталога), не через zsh, чтобы работало мгновенно.
- Реализуется в плане 2 вместе со строкой ввода.

### 6.2 Разрешения и вопросы агента *(решение исполнителя)*
- Режим разрешений по умолчанию — **без подтверждений** (`bypassPermissions`); в настройках
  вкладки можно переключить на «спрашивать».
- В режиме «спрашивать» запрос разрешения показывается **карточкой в ленте** с кнопками
  «Разрешить / Запретить» (через `--permission-prompt-tool` и небольшой MCP-сервер внутри приложения),
  а агент в панели получает статус «ждёт вас».
- Вопросы агента пользователю тоже показываются карточкой с вариантами ответа и статусом «ждёт вас».

### 6.3 Что поддерживается в режиме карточек *(решение исполнителя)*
- Отправка сообщения, прерывание (`esc` при фокусе на ленте или `⌃C`), продолжение сессии
  после перезапуска приложения (`--resume`, сессия привязана к вкладке).
- `/model`, `/compact`, `/clear` и пользовательские slash-команды отправляются как обычный ввод.
- Для всего остального (plan mode, интерактивные меню) есть команда «Открыть в классическом Claude»:
  та же сессия открывается в полноэкранном `claude` (TUI) в этой же панели.

### 6.4 Что такое «агент» в нижней панели *(решение исполнителя)*
- Панель показывает **сессию Claude текущей вкладки или панели**: главный агент и его субагенты
  (Task / Agent, связь через `parent_tool_use_id`).
- Агенты из других вкладок в панели не показываются. Об их работе говорит точка на вкладке,
  а уведомление приходит, когда агент закончил или ждёт ответа.
- «Шаг N из M» берётся из списка задач агента (TodoWrite). Если списка нет, шаг не показывается.

## 7. Разъём для своих агентов (на будущее)
Панель агентов и статус-бар берут данные из общего внутреннего формата
«агент → статус, текущее действие, шаги, модель, токены, родитель», а не напрямую из Claude.
Адаптер Claude Code — первая реализация. Позже к этому формату подключится свой агент владельца,
а место и вид его показа обсудим отдельно.

## 8. Что оставлено билдеру
- Структура кода, библиотеки внутри стека, формат конфига (рекомендуется TOML в `~/.config/kodevertex-terminal/`).
- Поведение мелочей: автоскролл, сворачивание длинного вывода, анимации.
- Когда текст считается «длинным» для режима чтения (ответы Claude — всегда, вывод команд — по разметке и размеру или по команде вроде `kv read file.md`).
- Иконка приложения в стиле KodeVertex (каретка с сайта).

## 9. Порядок поставки
1. Каркас: окно, вкладки, xterm + shell, темы, статус-бар (без Claude).
2. Блоки (OSC 133), строка ввода как в Warp, горячие клавиши, разделение экрана.
3. Интеграция Claude: карточки, режим чтения, нижняя панель агентов, контекст и модель в статус-баре.
4. Публичный репозиторий, README, CI, первый релиз `.dmg`.
